# TSF Connect Bootstrap

Публичный загрузчик для безопасного получения приватного установщика TSF Connect.

## Назначение

Этот репозиторий предназначен только для bootstrap-слоя: QR-авторизации GitHub Device Flow, получения проверенного релиза из приватного репозитория и запуска единого установщика.

Основной код TSF Connect хранится отдельно и остаётся приватным:
[`SCORP365/TSF-Connect`](https://github.com/SCORP365/TSF-Connect).

## Текущий статус

**Разработка. Сквозной сценарий собран, но чистая Ubuntu end-to-end проверка и публикация подписанного релиза ещё не выполнены.**

В репозитории подготовлены отдельные модули:
- `bootstrap/device_flow.py` — GitHub App Device Flow; refresh token не запрашивается, токен остаётся в памяти.
- `bootstrap/installer_flow.py` — связывает авторизацию, получение файлов манифеста из приватной ветки `release-manifests`, проверку подписи, загрузку архива и безопасное извлечение.
- `bootstrap/private_source.py` — получение архива только по полному commit SHA, проверка SHA-256 и безопасное извлечение без ссылок и специальных файлов.
- `bootstrap/manifest.py` — проверка Ed25519-подписи манифеста через OpenSSL и проверка идентификатора приватного репозитория.

Командная точка входа `python3 -m bootstrap.cli` связывает этапы: получает QR-авторизацию, проверяет подпись и архив, затем ищет только `installer/install.sh` внутри проверенного дерева. Если файла нет, установка завершается безопасно; обхода проверки или запуска из плавающей ветки нет. Режим `--retrieve-only` выполняет проверенное получение и извлечение без запуска установщика. Флаг `--resume` передаётся единому установщику для продолжения прерванной установки той же версии. Открытый ключ Ed25519 закреплён в `bootstrap/keys/tsf-release-ed25519-public.pem`; его SHA-256 fingerprint: `32dec00fc5c068ee7b2df2c07786c2698139c178b1b1c452a76d22d70066b9bf`. Ветка `release-manifests` и подписанный релиз ещё не опубликованы. Поэтому текущий код не является готовым установщиком и не должен использоваться на рабочем VPS.

Скрипт `bootstrap/run.sh` проверяет fingerprint закреплённого ключа и устанавливает только bootstrap-зависимости (`python3`, `qrencode`, OpenSSL, сертификаты). После проверки исходного публичного checkout запускайте `sudo bash bootstrap/run.sh`; для продолжения прерванной установки — `sudo bash bootstrap/run.sh --resume`. Сам приватный `installer/install.sh` теперь оркестрирует домен, preflight, зависимости, портал, HTTPS, RustDesk и ISPmanager. Однако ветка `release-manifests` и подписанный релиз ещё не опубликованы, а установка на чистой Ubuntu 24.04 с systemd ещё не проверена. До этих двух контрольных точек запускать на рабочем VPS нельзя.

Локальные тесты: `python3 -m unittest discover -s tests -v`. GitHub Actions запускает этот набор при изменениях тестовой ветки.

## Безопасность

См. [документ по архитектуре и безопасности](docs/BOOTSTRAP-SECURITY.md).

- Не использовать PAT или Client Secret.
- Не загружать исполняемый код из плавающей ветки.
- Не извлекать и не запускать приватный код до проверки подписи манифеста и хеша архива.
- Не сохранять GitHub-токен на сервере.
- Не менять DNS, firewall, ISPmanager и посторонние службы в процессе авторизации.

## Ветки

Рабочая разработка ведётся в `test/bootstrap-qr`. Ветка `main` не изменяется.
